Security

Isolation

Every session gets its own cloud sandbox: separate filesystem, processes and network identity. Sessions cannot see each other, and nothing persists after termination.

Secrets

  • Env vars are injected by the platform at boot — never typed into the terminal, never echoed.
  • Values are stored AES-256-GCM encrypted; only names are kept in plaintext.
  • Known secret values are masked in stored output, history and share views before anything is saved or sent.
  • Secrets are never logged and never returned by any API.

Authentication

You do not need an account. A session URL is the only credential: it is a 96-bit random identifier, it is never guessable, and it stops working the moment the session expires. Signed-in users get an Orin account session (revocation-checked) or a scoped MCP credential instead, which additionally lets them list their own sessions.

Keyless access controls

Because anyone may start a session, two limits bound the cost. A per-client window limits how many sessions one IP may start per hour, and a global cap on live sessions is counted in the database so it holds across every serverless instance rather than resetting per instance. Keyless sessions may not set environment variables and may not list sessions. An Authorization header that is present but malformed is rejected, never silently treated as keyless.

Data lifecycle

All session data — history, shares, env vars — is deleted at 8-hour expiry or on manual terminate. There is no archive, no backup, no recovery.
